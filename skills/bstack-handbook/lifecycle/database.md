# Database design

Saltbo's conventions for a relational schema. They choose between legitimate alternatives, so follow them even where another style would also be sound. They govern the tables a project owns. A library's own tables, such as an auth library's, keep the library's schema, and the project's tables do not copy its style. Migrations and live data are in [operate](operate.md), and repositories in [backend](backend.md).

## Decisions

- **Names.** Tables are plural snake_case nouns and columns are snake_case. A reference is `<entity>_id`, with the same name in every table. An instant is `<event>_at`, a boolean is `is_<state>` or `has_<thing>`, and who did something is `<verb>_by_<entity>_id`. A name says what the value is now, not what it meant in an earlier version. (2026-11-27)
- **Ids are UUIDv7, generated by the application.** They are a standard, sort by creation time so inserts stay local in the index, and need no coordination. They are stored in the engine's UUID type where it has one. A value handed out in a URL that must not reveal when it was made, such as a share link, is a separate random token. (2026-11-27)
- **One representation per kind of value.** Every instant is UTC with millisecond precision, stored in the type that fits the engine, such as an integer of epoch milliseconds in SQLite or `timestamptz(3)` in Postgres, and never a mix of units. Bytes and money are integers in their smallest unit. An enum is text whose values are defined once in shared code and enforced by a `CHECK`, never a magic number. (2026-11-27)
- **Every table has `created_at`, `updated_at`, and `deleted_at`, and a delete is a soft delete that leaves the row as a tombstone.** A tombstone keeps history, references, and sync working after a delete. Unique constraints and queries over live rows exclude tombstones through a partial index on `deleted_at IS NULL`. Removing a row or its content for good is a separate, explicit purge. (2026-11-27)
- **Business state is one `status` column.** Withdrawal, such as revoking a share, is `revoked_at`. No other column restates whether a row is live. (2026-11-27)
- **Every reference is a declared foreign key with its `ON DELETE`, and points at an id.** Never reference a path, a name, or anything else that changes. A hierarchy stores `parent_id` and derives its paths. A reference by a changing value breaks silently on a rename, and no constraint catches it. (2026-11-27)
- **Only top-level resources carry the tenant id.** A child reaches its tenant through its parent, so a tenant id is never copied down a chain of tables where it can drift from the parent's. (2026-11-27)
- **Each fact has one source of truth.** A stored total or counter derived from other rows is a cache, named or commented as one, and can be rebuilt from its source, such as a ledger. Two stored copies drift, and nothing says which one is right. (2026-11-27)
- **A table holds one entity with one lifecycle.** A price or other policy is not a column on the resource it applies to. A history of phases or events goes in a child table, not in a row of timestamp columns or a growing JSON array. (2026-11-27)
- **A structure that already exists is reused, not rebuilt for each feature.** Settings for one scope, such as a workspace, live in one table, not in a config table per feature. The same holds for deliveries to other systems with retry, for invitations, and for event logs. A new feature adds rows or a kind to the existing table. (2026-11-27)
- **Columns that are filtered or indexed are real columns**, and display-only fields share one typed JSON column. (2025-10-10, 2026-06-06)
- **Every index serves a query its comment names.** No index on a low-cardinality column alone, none that repeats a unique constraint, and none whose columns lead another index. Each index adds to the cost of every write. (2026-11-27)
- **Secrets are stored encrypted**, and the column name says so. (2026-11-27)
